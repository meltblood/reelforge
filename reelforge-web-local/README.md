# ReelForge Web / PWA

Одна веб-версия для iPhone и ПК. Приложение находится онлайн, а пользовательские фото и видео обрабатываются локально в браузере.

## Как это устроено

- GitHub Pages или любой обычный статический хостинг отдаёт только HTML/CSS/JS приложения.
- Исходное фото/видео не отправляется на backend.
- Декодирование, изменение кадров и кодирование MP4 выполняются на устройстве через WebCodecs.
- История recipes и fingerprints хранится в localStorage браузера.
- Медиадвижок загружается как JS-модуль; сервер для рендера не нужен.

То есть интернет нужен для открытия приложения, но сама обработка остаётся локальной.

## ПК — без EXE, BAT и команд

Открыть опубликованный URL в Chrome/Edge/Firefox/Safari, выбрать файл и обработать его. Ничего устанавливать на ПК не требуется.

## iPhone — без developer profile

1. Открыть тот же HTTPS URL в Safari.
2. При желании: `Поделиться -> На экран Домой`.
3. Открывать ReelForge как обычную иконку.

Профиль разработчика, TestFlight и App Store для этого не нужны.

## Бесплатное размещение через GitHub Pages без терминала

1. Создать public repository на github.com.
2. `Add file -> Upload files`.
3. Загрузить **содержимое папки `pwa`** в корень репозитория.
4. `Settings -> Pages`.
5. `Deploy from a branch` -> `main` -> `/ (root)` -> `Save`.
6. GitHub выдаст HTTPS-ссылку. Эту же ссылку можно открывать на ПК, iPhone и использовать как URL Telegram Mini App.

## Реализовано

- Фото и видео.
- MP4/H.264 на выходе.
- Reels 9:16 или исходное соотношение.
- Light / Medium / Strong / Manual.
- Built-in и пользовательские пресеты.
- Отдельные min/max диапазоны: zoom, pan X/Y, brightness, contrast, saturation, temperature, gamma, speed, trim start/end, detail.
- Новый random seed на каждый вариант.
- Минимальная дистанция recipe от уже созданных вариантов этого исходника.
- Quality gate по нескольким кадрам готового результата; слишком близкий результат автоматически создаётся заново.
- 1/3/5 вариантов за один запуск.
- Локальная история по fingerprint исходника.
- Исходный файл и готовый MP4 не загружаются на сервер приложения.

## Ограничения браузерной версии

- При включённом `Сохранить звук` скорость видео фиксируется на `1.0`, чтобы не получать рассинхрон без полноценного audio time-stretch.
- Поддержка конкретного входного кодека зависит от WebCodecs браузера.
- На мобильных устройствах очень длинные/тяжёлые 4K-видео могут упереться в память. Основной сценарий — короткие Reels.
- Приложение при запуске проверяет наличие H.264 encoder и не начинает обработку, если браузер его не предоставляет.
